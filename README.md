# Local RAG Pipeline

Grounded question-answering over your own PDFs — fully local, zero external API calls.

Upload a PDF, ask questions, get answers generated by a local LLM (Qwen 2.5) using only the content of that document. No data leaves your machine.

## Architecture

```
PDF → chunk → embed → store (SQLite)
                          │
Question → embed ─────────┤
                          ▼
              cosine similarity search
                          ▼
              top-3 relevant chunks
                          ▼
              Qwen 2.5 (via Ollama)
                          ▼
              streamed, grounded answer
```

## Tech stack

- **Backend:** FastAPI, Python
- **Embeddings:** sentence-transformers (`all-MiniLM-L6-v2`)
- **Storage:** SQLite (chunks + embeddings stored as BLOBs, similarity computed manually with NumPy — no vector DB)
- **LLM:** Qwen 2.5 (7B), served locally via Ollama
- **PDF parsing:** pdfplumber
- **Frontend:** React, TypeScript
- **Streaming:** Server-Sent Events (SSE)

## Prerequisites

- Python 3.10+
- Node.js 18+
- [Ollama](https://ollama.com) installed and running

## Setup

**1. Clone and install backend dependencies**

```bash
git clone https://github.com/Acestar21/local-rag-pipeline.git
cd local-rag-pipeline/backend
pip install -r requirements.txt
```

**2. Pull the model**

```bash
ollama pull qwen2.5:7b
```

**3. Start Ollama** (if not already running)

```bash
ollama serve
```

**4. Run the backend**

```bash
uvicorn main:app --reload
```

Backend runs at `http://localhost:8000`. Interactive API docs at `http://localhost:8000/docs`.

**5. Run the frontend**

```bash
cd ../frontend
npm install
npm run dev
```

## Usage

1. Upload a PDF via the UI (or `POST /ingest` with a `file` field)
2. Ask a question via the chat input (or `POST /query` with a `question` field)
3. Response streams in token-by-token

## API

**`POST /ingest`**
Multipart form, field `file` (PDF). Extracts, chunks, embeds, and stores the document, replacing any previously loaded document.

Response:
```json
{ "message": "PDF ingested", "chunks": 42 }
```

**`POST /query`**
Multipart form, field `question` (string). Returns a `text/event-stream` response, tokens prefixed with `data:`.

## Performance

Tested on a 471-page PDF (~610KB):

| Stage | Time |
|---|---|
| Ingestion (extract → chunk → embed → store) | ~55s |
| Query (retrieval → generation → full response) | ~18s |

Measured on local consumer hardware, no GPU acceleration.

## Known limitations

- Single-document only — a new upload replaces the previous one
- Top-3 retrieval struggles with broad summarization on very large documents
- No page-level citation tracking
- Character-based chunking (not sentence/semantic-aware)

## Future improvements

- Semantic/sentence-aware chunking
- Multi-document support
- Page-number citations
- FAISS or similar if scaling beyond a few thousand chunks
- Multi-turn conversation memory
